# 数据池只读检查

`storage-audit` 用于发现恢复前需要调查的异常，不执行修复，不读取工作空间内的用户文件，不验证文件内容或 XFS 实际项目编号。当前仅适用于生产目录数据池，不能检查 Docker Desktop 的命名卷。

在安装了包含该命令的平台镜像后，在 Linux 宿主执行：

```sh
docker compose -f /opt/dsh-cloud/prod.yml exec -T node-agent /usr/local/bin/entrypoint.sh storage-audit
```

命令读取节点的 `HOST_STORAGE_ROOT`，默认 `/var/lib/dsh`。输出 JSON；退出码 0 表示本次元数据检查没有发现列出的异常，2 表示存在检查项，1 表示无法完成检查，例如注册表缺失、损坏或路径不安全。退出码 0 不表示生产就绪，也不证明数据完整或配额实际生效。

| issue | 含义 | 处理原则 |
|---|---|---|
| pending | 创建或复制未确认完成 | 禁止当作正常数据启动；先确认中断阶段和完整副本 |
| missing | 有效记录对应目录缺失 | 保留注册表及相关快照，不创建空目录冒充恢复 |
| unsafe-entry | 记录对应项不是独立真实目录 | 调查链接/文件来源，不跟随或自动删除 |
| released-present | 已释放编号仍有同名目录 | 保留现场，调查删除/登记顺序，不重用项目编号 |
| unregistered | 池内有未登记且非已知元数据的项 | 可能是孤儿目录或临时文件；不能仅凭此结果删除 |
| recovery-present | 存在恢复副本 | 不代表副本完整；关联实例操作、镜像版本和 pending 状态判断 |

输出始终标注 `consistentSnapshot: false`：它没有取得节点排他锁，运行中的创建/删除可能令检查结果发生变化。用于最终恢复判断时，须在受控停机环境冻结写入，保留数据库、注册表和数据副本，再核对。此命令不提供冻结写入或自动恢复功能。

不得直接编辑注册表的 pending、released 或项目编号来消除告警。检查报告也不包含数据库的实例归属、镜像版本或操作日志，因此无法单独决定哪份数据应恢复。
