R1 不能以“先多复制一份再删除”就宣称完成：还须处理配额编号、失败残留、数据库版本、重试和断电恢复。安全切换前不得删除最后一份完整数据。当前代码尚不满足。

升级替换已有快照前先在数据库撤销旧 previousImage，写入失败则不修改快照，避免中断后把新快照与更早的镜像错误配对。两项不需要监听的状态测试通过；完整编排监听测试仍待许可。此措施可能令失败升级失去旧回滚入口，并不保存旧快照，也不替代版本化快照和持久操作；错误消息已明确说明这一代价。

当前恢复副本是过渡性数据保护：只有恢复镜像落库且请求的重建成功后才删除；数据库提交或重建失败时保留。副本使用独立项目配额，恢复期间额外占用一份当前数据的容量；容量不足则在删除活数据前失败。残留副本不能自动当作完整备份，尤其是进程在复制阶段被终止时。运维不得盲删 .recovery 来重试，应先保全数据并核查实际阶段；自动阶段识别、容量预检与断电持久性仍待实现。明确删除整个实例时也删除其恢复副本。

回滚现已在停机后、修改数据前删除旧容器，避免旧容器保留原挂载并被直接重启；删除失败不操作数据。手动回滚异常走错误状态和路由同步。恢复副本相关的上一轮 99 项测试通过；随后新增的旧挂载/删除失败回归尚未运行成功，所需监听权限申请被自动审批服务 HTTP 503 拒绝。

回滚在停止旧容器前将数据库状态设为 provisioning 并同步撤下路由，恢复镜像提交后状态为 stopped，仅重建成功才回到 running。撤路由失败不执行数据恢复；网关身份存储因此不再将恢复中的实例视为 running。三项无需监听的定向编排测试及类型检查通过，使用数据库/路由桩，不代替真实浏览器撤权时限验收。进程在 provisioning 阶段中断仍需要持久任务恢复。

生产池创建/复制的配额记录现带持久 pending 标记；配额设置及复制成功、GNU sync -f 刷盘后，才以同一项目编号确认完成。未完成数据拒绝 ensure、复制源和配额有效声明，防止新流程中断留下的半成品被正常重建。72 项池/驱动测试及类型检查通过，包括新建注册表对象重新读取未完成状态、拒绝错误项目编号确认、拒绝使用半成品且保留原文件。实际 sync -f/XFS 断电行为未在 Linux 验证；刷盘增加时延，宿主 I/O 错误会阻止确认。旧版本已留下的无标记半成品无法自动识别；开发命名卷未接入该标记。完整阶段恢复与镜像/数据库一致性仍是 R1/R2 缺口。

## 3. 验证记录与边界

安装器强制应用 FORWARD 平台来源分流及 egress 链，阻断私网/链路本地/特殊 IPv4 和已识别 Docker 网桥目的地（包括其他业务的自定义网桥名）；只允许公网 IPv4 TCP/UDP，IPv6 主动出站拒绝，已建立回复方向返回宿主规则继续处理。脚本桩测试检查公共 INPUT/FORWARD 不被清空及其他来源不被选择；安装顺序测试检查网络步骤失败不继续启动服务。没有实际修改本机防火墙；macOS 不能验证 Linux IPv6 分支、Docker NAT、重载顺序和内核包路径。规则生成后新建的自定义网桥及特殊路由仍需动态策略，完整网络阻塞项未关闭。依赖内网模型/Git/IPv6 的工作空间升级会受影响，目前尚无按实例例外配置。

控制台日志 SSE 禁止缓存，并处理等待日志期间断连、源流错误、单响应超过 4 MiB 或发送队列超过 1 MiB 时关闭连接。五项流测试及类型检查通过；超限日志会截断，需减少请求行数。该限制仅覆盖 SSE 层，不限制 Docker SDK 在返回日志前已缓冲的内容，节点日志读取的上游内存边界仍待实现，不据此宣称已解决日志内存耗尽风险。

生产启动拒绝非空 EXTRA_TRUSTED_ORIGINS，防止开发来源或工作空间来源被配置为控制台受信来源；本地开发保持可配置。升级前必须清空该项，使用外部独立前端的部署需先迁回控制台同源入口。27 项生产配置/应用回归通过；不替代浏览器联合攻击验收。

## 4. 攻击链与剩余风险

逐环验证“普通/共享账号 → 平台提权 → 恶意工作空间 → 宿主权限 → 其他用户数据”，不因前一环受阻跳过后一环。

- **共享账号内部**：同账号的数据与工作空间可互见是用户接受的行为；跨账号访问不属于例外，必须阻断。
- **平台提权**：权限来自服务端会话，不接受请求体角色/伪造身份头；已有认证库回归，不代表不存在未知越权。
- **工作空间服务**：dsh、Caddy、插件、脚本及其日志均不可信；其他账号的最终边界必须在工作空间外，测试包含主动恶意后端。
- **宿主与控制面**：节点具有宿主高权限；控制面仍有数据库、路由写权限和全实例管理能力。减少直接挂载不保证控制面失陷后数据保密。
- **共享内核**：普通 Docker 两档都不能保证抵御内核/运行时逃逸；非 root 也可能利用漏洞。宿主 root 可读同机已挂载数据/秘密，磁盘加密无法解决。抗宿主内核失陷需要更强运行时或不同信任域。
- **已有 Linux 服务**：标准档目标为经验证的受限共存，目前尚未验收；加固档需要专用受信 Linux，可用专用 VM。安装较早不等于不合格；失陷系统不能靠加固安装恢复可信。原业务 root/Docker 权限威胁平台，平台逃逸也威胁原业务。
- **公网外传**：加固代理即使完成，允许 HTTPS 仍允许代码发送它可读的数据，私网阻断不等于防止一切外传。
- **现存实例**：新策略仅在新建/重建施加；未核验旧实例必须标记未迁移，不能默认视为加固。

## 5. 完成判断

当前本地仍有可实施工作，不因缺少 Linux 真机就将整体判为阻塞。最终上线需要受支持的专用 Linux 验证环境；macOS 不能替代安装、XFS、LSM、网络重载、宿主重启验收。

只有 R1–R9 实现和对应证据全部完成才能关闭目标。文档完成、测试数量增加或某阶段通过均不代替完整交付。
