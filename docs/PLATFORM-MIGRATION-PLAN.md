# dshcloud 改造落地文档

日期：2026-09-19。目标见 [目标方案](PLATFORM-TARGET-DESIGN.md)。状态：实施计划，未修改代码、认证、数据库或宿主配置。

## 1. 现状与改造范围

当前已具备邀请、用户与工作空间管理、版本目录、升级回滚、数据池、独立网络、认证入口及基础测试，不需要重写产品。改造的主线是把这些能力整合成可验收的两档部署，并补足外部强制边界和恢复能力。

本文是改造计划，不是实时完成清单。当前工作树已继续实施认证网关、节点服务拆分和存储保护，但仍未完成生产验收；逐项状态及证据边界统一记录在[生产落地状态](PRODUCTION-READINESS.md)。已有安全组件集成测试记录，不等于新网关的完整浏览器联合验收或 Linux 端到端验收。工作树不能当作线上版本，文档更新不表示重新发布或部署。

## 2. 先解决业务兼容性，不先铺架构

第一步在可重装的 Linux 测试机上，以目标容器参数运行当前支持的 dsh，确认「非 root + 只读根 + CapDrop ALL + NNP + 默认 seccomp + LSM」能否完成真实工作。

测试不能只运行 `echo`。建立带真实配置、插件、会话和文件的工作空间，验证模型调用、工具执行、语言依赖安装、编译、终端、网络、预览及升级。外部模型测试使用专用限额账号，不将 key 放进报告或通用镜像。

系统依赖以管理员镜像预装为目标。先列出实际业务需要的依赖集合，不凭空增加 IDE、GPU、嵌套 Docker 或公开分享。如果必须保留即时 root 装包，则这是目标方案的阻塞决策，先重新设计，不能把能力缺失藏在错误信息里。

现有 gVisor/bwrap/Landlock 记录只作已知风险输入。重测须记录 dsh、内核、Docker、runc、LSM 版本以及实际命令；旧探针成功不等于新组合中的完整会话成功。

## 3. 分阶段实施

### P0：冻结要求与验收基线

交付：业务验收脚本、支持能力清单、环境矩阵、旧数据样本与恢复样本。

- 以目标文档的业务表为准，标明已确认业务与方案取舍，尤其是系统包安装、加固档出网和第二注册域。
- 最小基础设施：一台可重装 Linux VM、一个独立测试客户端、测试域名与备份目的地；不要在开发 Mac 上执行生产安装脚本。
- amd64 与 arm64 只有各自实际通过后才支持；不把多架构镜像构建成功当作双架构验证。
- 先完成上一节兼容实验；记录资源额外开销与不可用功能，不编造性能数字。

退出条件：完整 dsh 工作流通过目标参数，产品限制可说明，旧数据可恢复。

### P1：共同容器基线与数据安全

主要文件：`packages/instance-spec/src/schema.ts`、`renderers/*`、`apps/server/src/runtime/docker/driver.ts`、`instance/data-store.ts`、`docker/instance-image/*`。

- 定义版本化 `RuntimePolicy`，由服务端选择；普通用户不可传任意 capabilities、挂载、sysctl 或镜像。
- 落实只读根、CapDrop ALL、NNP、非 root、临时空间上限、日志轮转和默认 seccomp；保留必要的 masked/readonly 保护，升级引擎时验证覆盖表。
- 调整日志与临时文件路径，确保所有持久内容在 `/data`。语言依赖与插件在数据中，系统依赖在镜像中。
- 迁移旧数据必须先停机。不能对正在被不可信进程修改的树执行高权限递归操作；校验挂载、符号链接、硬链接和路径逃逸，禁止归档解包越界。
- 对属主迁移记录明确阶段，不能仅凭顶层 uid 就推断历史迁移完整；异常中断应可安全继续。保留迁移前副本与 uid 方案信息供恢复。
- 设置实例资源与平台总预算；镜像、快照、日志不挤占数据库保留空间。

退出条件：新建、旧数据重建、升级、失败回滚全部通过；超额真实被拒；依赖安装和插件真实渲染正常。

### P2：两档网络策略与宿主准入

主要文件：新增节点网络策略模块；调整 `runtime/docker/driver.ts`、`scripts/install.sh`、`docker/compose/*`。

- 为本平台的桥建立资源登记，设置容量可控的地址池并检测与宿主/VPN网段冲突；不修改其他 Docker 网络。
- 标准档阻止其他实例、宿主全部地址、内部网段、元数据；管理员允许的私有模型地址例外精确到实例/地址/端口。
- 加固档增加 DNS、HTTP(S) 代理、直连封锁、带宽和连接控制；代理对解析结果、CONNECT、重定向和 IPv6 逐项测试。
- 锁定首批支持的 Docker 防火墙后端和 Linux 发行版；不要尝试用一份未经验证的 iptables/nftables 脚本覆盖所有宿主。
- 规则必须先于容器执行生效；生产禁用绕过策略的 Docker 自动重启路径，由受信启动流程恢复网络后再启动负载。
- 建立漂移检测：不能原子修复时隔离/停止受影响实例，保留数据并告警。明确 Docker、firewalld/ufw reload 与宿主重启的恢复顺序。

退出条件：跨实例、宿主公网/私网、DNAT/hairpin、IPv6、元数据均按预期阻断；公网业务和私有模型例外可用；其他容器网络不受影响。

### P3：访问网关与认证迁移

主要文件：`auth.ts`、`http/forward-auth*`、`http/session-routes.ts`、`instance/traefik.ts`、`platform-routes.ts`、`apps/web/src/pages/OpenWorkspacePage.tsx`；新增网关及会话存储。

现状 → 根因 → 改后形态 → 代价：父域平台会话用于所有子域认证 → 用户内容与管理身份共享浏览器作用域 → 控制台 host-only + 网关单实例会话 → 新增授权交换和撤权机制，迁移需要用户重新登录。

- 实现目标方案的事务、授权码兑换和会话绑定；成熟协议组件优先，不手写加密算法。
- 网关自行按 Host 查注册映射，忽略客户端伪造的实例头、用户头、签名头和转发头；只信任配置的上游代理。
- 平台 Cookie 与保留头双向过滤；测试多个 Set-Cookie、重复 Cookie 名、父域、编码和大小写，不做字符串 replace。
- 未登录浏览器页面才进入登录流程；API/WS 使用明确拒绝语义，禁止把任意请求体转发到登录端点。
- 注册撤权事件与 WS/SSE 定期校验，达到最长 30 秒的目标；网关与 DB 故障时验证 fail-closed。
- 新会话存储只保存随机凭据的哈希；授权码消费用数据库原子操作。
- 先在测试域并行验证，正式切换使用维护窗口：摘旧入口 → 清理旧父域 Cookie、失效旧会话 → 发布新链路 → 双账号浏览器验证 → 开放访问。不得长期同时接受新旧父域会话。

退出条件：页面/API/WS/SSE 的未登录、非 owner、owner、注销和封禁全通过；真实浏览器 Cookie 投毒、登录 CSRF、授权码重放与跨实例兑换失败。

### P4：拆出节点代理，移除控制面宿主权限

建议新增 `apps/node-agent/`，保留现有 RuntimeDriver 的业务契约，逐步将 Docker、存储和网络操作搬到代理。不要为迁移同时重写 Fastify、React 和数据库层。

- 本地 Unix socket + 文件权限/对端身份，接口版本化；请求带操作 ID、实例 ID、策略版本。
- 创建、停止、配额、快照等提供明确 RPC；拒绝任意 exec、宿主路径、原始 Docker 请求。必要工作负载 exec 限定实例、用户及用途，不是宿主执行入口。
- 代理从受信登记解析 storageKey 和网络，核对自身资源标签，禁止操作非本平台资源。
- 控制面移除 docker.sock、/dev、池目录和 SYS_ADMIN；生产 compose 收敛为普通服务。
- 用数据库操作表和实例锁覆盖创建/升级/删除/迁移；重试必须返回同一结果或继续同一操作，不重复分配数据与端口。
- 每搬一个方法就跑原契约测试；切换后禁止后台继续存在直连 Docker 的旧入口。

退出条件：控制面不能直接访问宿主设备和 Docker；代理拒绝越权路径/镜像/资源请求；进程中断后升级或删除可恢复。

### P5：安装 profile、发布和运维闭环

主要文件：`scripts/install.sh`、`.github/workflows/*image.yml`、`docker/platform/*`、管理台设置与诊断页。

- 同一安装器支持 standard/hardened，持久记录目标 profile、策略版本和上次检查；更新默认保留原档位。
- `doctor` 检查实际运行容器、网络、配额、LSM、镜像 digest、备份状态；不能只检查配置文件存在。
- 加固档不接受能力缺失或静默降档；标准档也不容许认证、网络或硬配额底线失效。
- 镜像 digest 固定、SBOM、漏洞检查、发布签名/来源校验；维护已验收的 dsh/内核/运行时组合。
- 提供备份计划、单实例恢复、整机恢复、告警与事件审计；秘密不写日志，备份凭据不进入工作空间。
- 加固档完成外部备份恢复验证；运行策略漂移和严重漏洞处理有明确责任人与动作。

退出条件：新装、重复安装、升级、重启、档位切换、卸载保留数据、恢复全部有记录；安装成功与生产就绪分开呈现。

### P5 补充：已有 Linux 服务的共存改造

两档的支持规则以目标文档 §10.1–10.3 为准：标准档支持经过检查的混部；加固档允许已有系统工具及受支持的运维软件，但要求不承载其他业务的专用主机。不是强制重装 Linux，也不是可以无条件在任意现存服务器上安装。

需要新增的交付：

- 只读 `preflight`/`--dry-run`：收集发行版、运行时、cgroup/LSM、端口、已有代理、防火墙管理器、路由/VPN、卷与挂载、可用容量。输出通过/可调整/阻塞及精确理由，不输出秘密。
- 安装计划与资源清单：明确将新增的包、服务、目录、端口、挂载、规则、磁盘预算和代理接入方式；对未知非空目录、同名资源和未受管挂载直接拒绝。
- 入口两模式：独占 80/443，或已有反向代理接入；新增已验证的配置模板和 WS/SSE/Host/认证回调测试。不能仅换个端口却仍要求自己占用 80 做 ACME。
- 全局操作护栏：不改已有 daemon.json、不自动升级/restart Docker、不关 LSM、不清空防火墙、不格式化已有盘；必需全局变更时停止自动流程，交给管理员维护后重跑预检。
- 共存容量策略：显式平台 CPU/内存/磁盘预算和并发限制，禁止默认吃掉宿主 80% 剩余磁盘；检查运行日志、镜像及备份暂存也有预算。
- 安装回退与卸载：记录资源所有权，保留既有配置和数据；不能用全局 prune 或回灌旧防火墙快照覆盖其他服务的新改动。

当前实现差距：生产 compose 默认占用 80/443，已有反向代理接入尚未实现；安装存储默认容量和宿主持久化操作需要增加共存预算、计划和归属检查。`--harden-host` 已改为匹配平台保留的 `dshw` 网桥前缀及带归属标签的旧实例网桥，并增加冲突拒绝与脚本桩测试；这不等于完整出站隔离，也尚未证明在真实 Linux 防火墙重载、重启及混部环境中可靠。上述未完成项不能写成当前安装脚本已提供的保证。

共存测试至少包括：宿主 Nginx 已占用 80/443；已有普通 Docker 网站与数据库；已有非空存储目录；Docker 版本不支持；网段与 VPN 冲突；受支持防火墙 reload；安装中断后重跑；其他服务并发修改规则后卸载本平台。记录安装前后原服务 HTTP、数据库连接、容器状态、SSH 管理链路、规则与挂载变化；原服务的资源不能被重建或删除。

标准档另做双向压力测试，测本平台负载对原服务、原服务负载对本平台的影响，不写「完全无性能影响」。加固档测试检测到其他业务时拒绝认定为加固生产就绪；安装器无法完全自动识别所有业务，需管理员声明专用用途并持续维护。

最终用户文档必须分别列出两档的宿主前提、会修改什么、不自动修改什么、已支持的共存矩阵、已有入口配置、失败恢复和卸载行为。版本发布时与真实安装器能力同步，不能提前把本设计写成现有功能。

两档安装指南都必须说明双向影响：原服务获得 root/Docker 权限会危及平台，平台工作空间发生内核逃逸也会危及原服务。加固档指南另提供从混部系统迁往专用 Linux VM/主机的流程：备份数据与归属信息，在新环境验收并恢复，安排停止旧端写入后完成最终同步，切换 DNS/入口并验证，再保留旧环境用于受控回退。禁止两个环境同时写同一份工作空间数据；切换后已有新写入时，不能简单切回旧数据，须先停止写入并制定数据回迁方案。

## 4. 数据与协议变化

以下是拟议字段/实体，不是已经批准的数据库迁移；实施前按项目约定先解释具体设计再执行。

| 实体 | 需要表达的事实 |
|---|---|
| 平台设置 | 目标部署档位、策略版本、工作空间域、加固检查状态 |
| 实例 | desired/applied policy version、策略检查时间与失败原因；保留现有 ownerId/storageKey |
| 操作记录 | 操作 ID、实例、类型、幂等键、阶段、输入版本、错误、开始/完成时间 |
| 访问事务/会话 | 凭据哈希、实例、用户、源会话、过期/撤销、授权码已消费状态 |
| 审计事件 | 操作者、目标实例、动作、策略变化、结果；不保存会话明文或用户 key |
| 备份清单 | 实例 ID、storageKey、版本、时间、一致性方式、校验值、恢复状态 |

先做可兼容的增量迁移，旧实例标记为「策略未验收」，不能用默认值将其视为已加固。收缩旧字段必须等新链路稳定并完成备份。不要为了单机代理提前引入复杂集群调度表。

## 5. 现存安装怎么迁

1. 清点平台/实例版本、卷类型、实际属主、网络、数据量和未完成操作；不要仅根据数据库状态迁移。
2. 先备份 DB、逐实例数据与平台密钥，验证至少一个样本可恢复；计算全量副本空间和停机时间。
3. 发布兼容旧数据的过渡版本和新增表；部署代理/网关但不提前接管全部流量。
4. 一个测试实例完成 P1/P2/P4，再迁一个真实低风险实例，观察后分批迁移；实例级锁防止同时升级、备份、删除。
5. 每个实例：停止入口 → 停容器并确认进程退出 → 快照 → 数据迁移 → 策略/配额就位 → 创建 → 业务检查 → 开放入口 → 标记 applied。
6. 认证迁移采用独立维护窗口，按 P3 失效旧会话。变更注册域时给出新地址，旧域不得继续代理未认证流量。
7. 所有实例和宿主强制项通过后才将整个平台标为 hardened。旧容器不能等「以后升级时再说」。
8. 回收遗留网络、入口与权限必须按资源清单执行，不按模糊前缀批量删除。

回滚分三种：应用镜像回滚、数据快照恢复、平台/认证策略回滚。它们不是同一个按钮。新网关或强制策略故障时先保持拒绝访问，修复或恢复已验证的兼容版本，不能为了恢复服务裸放旧入口。恢复旧策略意味着重新评估部署档位，不继续显示已加固。

## 6. 验收矩阵

| 类别 | 必须验证的动作 | 通过标准 |
|---|---|---|
| 业务 | 对话、命令、依赖、Git、终端、流式响应、预览 | 同档位支持清单内全部可用，不能只有容器启动成功 |
| 定制 | 安装标准插件、改配置/UI patch 后升级重建 | dump-config、bundle 获取、控制台、真实渲染四级都通过 |
| 身份 | 未登录、他人、本人访问页面/API/WS/SSE | 拒绝/拒绝/允许；平台凭据不抵达后端 |
| 浏览器 | 恶意子域种 Cookie、伪造 state、重放授权码 | 不接管控制台或其他空间；同 owner 两空间也隔离 |
| 撤权 | 封禁/注销时已有 WS/SSE 持续发送 | 30 秒目标内断开，后续请求拒绝 |
| 网络 | 扫邻居、网关、宿主公网、内网、IPv6、元数据 | 无未授权访问；允许的模型/依赖下载仍工作 |
| 代理 | 直接 IP、CONNECT、重定向、DNS rebinding | 不绕到禁止目的地；不能直接绕过出站策略 |
| 资源 | 进程风暴、内存超额、大文件、小文件、刷日志、占临时盘 | 限额生效，控制台和邻居仍可响应 |
| 文件边界 | 符号链接、归档路径、并发改目录、旧数据属主 | 不能让高权限迁移/恢复访问实例目录外 |
| 生命周期 | 升级中杀控制面/代理，镜像坏、快照满、数据卷丢失 | 恢复同一操作或报错保留数据，不假建空卷 |
| 宿主故障 | Docker 重启、宿主重启、规则被清、挂载丢失 | 未就绪不启动负载，既有失防实例被隔离并告警 |
| 灾备 | 单实例恢复、空白宿主全量恢复 | 数据、归属、版本可核对，不能用另一实例备份替代 |
| 共存 | 标准档宿主有其他 Docker 服务 | 安装、规则更新、卸载不改变其他服务的网络 |

测试分三层：纯逻辑单元测试；真实 Docker/数据库/入口集成测试；专用 Linux 上的业务与攻击验收。浏览器认证必须用真实浏览器双账号；内核、配额、LSM 与重启必须真机。通过单元测试不替代后两层。

强制策略发布还应有一次独立复核，重点看认证交换、节点代理输入、网络绕过和数据迁移。复核是建议的发布门槛，不是声称已完成外部审计。

## 7. 最小执行组织与优先级

由总负责人统一确认业务取舍、验收和发布。一个主要开发者可以按 P0 → P1 → P2 → P3 → P4 → P5 顺序推进；每个阶段找另一位具备相应经验的人复核关键边界即可，不需要先组建专门安全团队。

最先交付 P0 兼容实验与 P1 共同基线，再补 P2/P3，之后收敛宿主权限与安装运维。阶段不是可跳过的安全等级：P5 完成前不要对外宣称加固部署已经成立。

当前不提供确定工期：命令沙箱/LSM 兼容、数据量导致的停机、目标发行版和模型出网范围尚需实测。P0 完成后按实际结果估算各阶段，避免把需要系统验证的改造写成几天的参数调整。

## 8. 文档收口与需确认的设计取舍

本轮只新增目标方案与本计划，保留旧文档作为历史与现状证据。实施时应同步更新 ARCHITECTURE、DECISIONS、OPEN-QUESTIONS、PLAN、AGENTS 及中英文 README，避免目标设计被误读成运行现状。

重点纠正：seccomp 不是按命令名过滤；XFS 存储已存在单元测试；固定 uid/NNP 的代码落地与真机上线分开表述；强制策略不能只等存量实例自然升级。

进入代码实施前，需要确认的具体取舍为：

- 系统依赖走管理员镜像，用户依赖/插件/UI 定制保留在 `/data`。
- 加固档使用专用宿主和独立注册域，默认出站 HTTP(S) 代理，特殊协议逐实例授权。
- 接受普通 Docker 共享内核风险；若不接受，则第二档必须改成更强运行时并重新计算宿主成本。
- 同意认证迁移重新登录、逐实例迁移停机，以及新增节点代理/访问网关的维护成本。

这些是完整方案需要审阅的产品和架构选择，不是要求先授权才把文档写完。下一步实施仍遵守仓库「隔离边界 / 数据模型 / 认证链路变更前解释并确认」的约定。
