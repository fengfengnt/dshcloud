# 容器隔离实测：最小方案

> 配套 [CONTAINER-ISOLATION-PAPER](CONTAINER-ISOLATION-PAPER.md)。
> 目的：在**任意一台宿主**上，用最小的工作量重测那篇论文的核心结论。
> 这不是复现整篇论文 —— 只保留**结果会改变决策**的项。文献结论（清单盲区、补丁节奏）
> 和需要专门工具的项（侧信道）都不在这里。

## 〇 三条纪律（论文 §4）

1. **对照测量**。每项都要有「改之前 / 改之后」两次读数，单次读数不算证据。
2. **真实流程**。加固类结论不以「容器起得来」为准，要跑 起实例 → 装包 → 跑命令 → 快照。
   这类改动的典型事故是**静默失败**：容器照常起，agent 跑到中途才 `EPERM`。
3. **不继承结论**。换宿主或换运行时，既有结论一律作废重测。

## 一 先固化环境

不记这一节，下面的表就不可比。**换任一项 = 全部重测。**

| 项 | 怎么取 |
|---|---|
| 内核版本 | `uname -r` |
| 引擎版本 | `docker version --format '{{.Server.Version}}'` |
| 镜像 digest（不是 tag） | `docker inspect --format '{{index .RepoDigests 0}}' <镜像>` |
| 宿主内存 / 核数 | `free -m`、`nproc` |
| 有无 KVM | `ls -l /dev/kvm` |
| 根文件系统类型 | `findmnt -no FSTYPE /` |

## 二 六个必测

| # | 测什么 | 需要 | 会写盘 |
|---|---|---|---|
| 1 | 实例 ↔ 实例 | 容器内 | 否 |
| 2 | 实例 → 宿主 | 宿主 root + 容器内 | 否 |
| 3 | 文件系统配额 | 宿主 root + 容器内 | **是** |
| 4 | 沙箱链两档 | 容器内 | 否 |
| 5 | 参数是否真传下去 | 宿主 + 容器内 | 否 |
| 6 | 八文件对照 + 绕过 | 宿主 root + 容器内 | 否 |

### 1 实例 ↔ 实例：分段生效了吗

在实例内做，**实例镜像里没有 `nc`**，用 `curl`。

```
cat /proc/net/arp
curl -m 3 -sS http://<邻居实例IP>:<端口>
```

- **判据（通过）**：`arp` 里只有网关一条；跨实例 `curl` 超时（exit 28）。
- **推翻长什么样**：邻居端口有响应、`arp` 里出现邻居条目 → 实例之间共享 L2 广播域，
  于是直连、扫描、ARP 欺骗三条路径同时成立，且这条路径上转发的是明文。
- **推翻后改什么决策**：分段是宿主层唯一的实例间边界，必须修，不能靠上层认证补。

### 2 实例 → 宿主：宿主上哪些监听在射程内

宿主上起两个监听，实例内分别 curl 宿主的桥网关地址：

```
python3 -m http.server 8000 --bind 0.0.0.0
python3 -m http.server 8001 --bind 127.0.0.1
```

- **判据（通过）**：绑 `0.0.0.0` 的**可达**，绑 `127.0.0.1` 的**被拒**。
- **推翻长什么样**：回环也通 → 宿主回环上的所有监听对这个实例开放。
- **推论**：绑 `0.0.0.0` 意味着宿主的 SSH 与一切非回环服务在实例射程内；
  容器引擎没有原生开关，只能宿主侧 INPUT 规则处理。
- **对照**：同样两条命令在开发机（Docker Desktop）上跑一遍 —— 那里预期**两条都通**。

### 3 配额：上限真的落在文件系统的分配路径上吗

⚠️ **这一项要真写盘。用一次性实例 + 一次性池，不要在工作实例的工作区里做。**

三个读数，缺一不可：

```
dd if=/dev/zero of=<实例目录>/f bs=1M count=400     # 期望停在配额值 + ENOSPC
df -h <实例目录>                                     # 期望报的是配额值，不是池子大小
```

再单独量 **inode**：只限字节时，数百万个零字节文件即可耗尽宿主 inode。
用 `touch` 批量造零字节文件，看创建是否被拒。

- **判据（通过）**：字节停在限额且返回 `ENOSPC`；容量视图 = 配额值；inode 超限同样被拒。
- **静默失败那一项单独看**：读取用量不需要特权，**写入限额需要**；缺特权时限额不生效
  且**不报错**。所以检查平台在启动实例时是否**设置后读回校验** —— 没有这一条就等于没设。
- **开发机上预期做不到**：linuxkit 内核裁掉配额支持，挂载选项返回 `EINVAL`；
  那里只能退回无配额的命名卷，界面上必须显示「无上限」，不能显示一个假数字。

### 4 沙箱链两档：这个运行时能不能选

在目标运行时里逐档探测，**记录每档的 errno**，再跑一遍完整流程确认命令真能执行。

- **判据（通过）**：两档里至少一档可用，且完整流程照常。
- **注意语义**：应用链是「失败即拒绝执行」。所以两档全灭的表现不是「慢」，是
  **任何命令都不会被执行** —— 那种运行时对本负载不是更差的选项，是**不能运行**的选项。
- **不继承**：标准运行时下成立的档位，换运行时后必须重测；同一档名不能假定同样可用。
- **这一条只影响「功能是否可用」，不影响「边界是否成立」**：应用自带的沙箱住在它自己
  约束的可写空间里，不写进安全论证。

### 5 参数是否真传下去：「设了」不等于「生效」

改一个资源参数（进程数上限最省事），在三个位置各读一次：

```
docker inspect <容器> --format '{{.HostConfig.PidsLimit}}'
cat /sys/fs/cgroup/pids.max                    # 容器内
```

- **判据（通过）**：界面设置值 = `HostConfig` = 容器内读回，三个一致。
- **推翻长什么样**：界面能改、`HostConfig` 是默认值、容器内读回也是默认值 → 驱动没传。
- **推广**：这一条对所有资源类参数都成立，每类都要有一条这样的用例。

### 6 信息隐藏：八文件对照，以及它的结构性上限

**对照测量**：同一个容器，挂载前后各读一次这八个文件，逐文件标「生效 / 不生效」。

```
meminfo  uptime  swaps  loadavg  stat(btime)  cpuinfo  diskstats  slabinfo
```

- **判据（通过）**：逐一记录取值变化。**「提供了但没改变取值」等于没生效** ——
  挂上去只增加了挂载点，不代表它盖住了。
- **绕过验证（这一条才是重点）**：在**已挂载**的同一容器里，跑一个直接调 `sysinfo(2)`
  的程序（`busybox free`、若干语言运行时都属于此类），同时读 `/proc/meminfo`。
- **判据**：若 `/proc/meminfo` 报限额而 `free` 报宿主值 → 这一类方案只篡改了
  **文件读取路径**，准确表述是**降低可读性，不是边界**。
- **为什么这一层要单独测**：它不是「敏感文件」问题，泄漏的是**形状** ——
  宿主的内存总量、开机时刻、CPU 型号与核数。这些数字让租户能指纹宿主，
  并把宿主的负载变化与重启当作跨租户侧信道。

## 三 三个顺带（便宜，各一条命令）

| 项 | 怎么做 | 判据 |
|---|---|---|
| **默认遮蔽表漂移** | 在**两台**宿主上，用同一镜像起容器，逐个探测默认遮蔽条目是否可读（`/proc/interrupts` 是已知的漂移项），数出条目数 | 两台条数/差异项不一致 → 显式设置该项时默认表被**整份替换**，写死一份并对齐测试 |
| **DMI** | 容器内读 `/sys/devices/virtual/dmi/id/*` | 能读到机型 → 宿主身份可指纹；它可被运行时遮蔽覆盖，与运行时选择无关 |
| **执法可绕过** | 同一动作换三种写法：改名（`cp` 后执行）、换库调用（语言运行时直接调同一系统调用）、符号链接 | 三种里只要一种没被拦 → 该执法是**纵深不是边界** |

## 四 不在这份方案里

- **侧信道**（页缓存计时、内核锁争用、CPU 频率指纹）：需要专门工具与统计方法，
  不属最小集。**关键是别把它的缺失当成「已藏干净」** —— 换到硬件虚拟化也收不干净。
- **时间命名空间偏移量**：机制在内核里，但运行时不暴露开关，**测不了**。
- **镜像供应链**（签名 / SBOM / pin）、**宿主侧运行时检测选型**：另一条线。
- **文献结论**（清单盲区、补丁节奏、逃逸基准）：不是本机可测的量。
